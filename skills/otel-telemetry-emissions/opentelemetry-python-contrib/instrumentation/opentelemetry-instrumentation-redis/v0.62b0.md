# Redis instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `<Redis command>` (or `redis.search` / `redis.create_index`) | CLIENT | `db.statement`; `db.redis.args_length`; `db.system`; `db.redis.database_index`; `net.peer.name`; `net.peer.port`; `net.transport`; `redis.create_index.index`, `redis.create_index.fields` (FT.CREATE); `redis.search.index`, `redis.search.query`, `redis.search.total`, and dynamic `redis.search.xdoc_<document>.<field>` attributes (FT.SEARCH) | Spans are emitted for synchronous/asynchronous, cluster, and immediate command execution when instrumentation is enabled. FT.CREATE and FT.SEARCH attributes are added when the corresponding command is handled by the synchronous command wrapper. Unix-socket connections emit `net.peer.name` and `net.transport` without `net.peer.port`; TCP connections emit all three connection attributes. |
| `<space-separated Redis commands>` (or `redis` for an empty/invalid pipeline) | CLIENT | `db.statement`; `db.redis.pipeline_length`; `db.system`; `db.redis.database_index`; `net.peer.name`; `net.peer.port`; `net.transport` | Emitted for synchronous/asynchronous pipelines and cluster pipelines when instrumentation is enabled. Unix-socket pipelines omit `net.peer.port`. |
