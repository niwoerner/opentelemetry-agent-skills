# @opentelemetry/instrumentation-grpc

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `grpc.<service>/<method>` | CLIENT | `rpc.system`, `rpc.service`, `rpc.method`, `rpc.grpc.status_code`, `server.address`, `server.port`; configured `rpc.request.metadata.<key>` and `rpc.response.metadata.<key>` | Client spans are created for unary, client-streaming, server-streaming, and bidirectional calls. `ignoreGrpcMethods` suppresses matching methods. Metadata attributes require the corresponding `metadataToSpanAttributes.client` configuration. Status and response metadata are added when the call completes/returns them; error attributes `grpc.error_name` and `grpc.error_message` are added on errors. |
| `grpc.<service>/<method>` | SERVER | `rpc.system`, `rpc.service`, `rpc.method`, `rpc.grpc.status_code`; configured `rpc.request.metadata.<key>` and `rpc.response.metadata.<key>`; on errors, `grpc.error_name`, `grpc.error_message` | Server spans cover unary, client-streaming, server-streaming, and bidirectional handlers. `ignoreGrpcMethods` suppresses matching methods. Metadata attributes require the corresponding `metadataToSpanAttributes.server` configuration. Status and response metadata are added when the handler returns/emits them. |
